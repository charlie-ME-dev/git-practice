## 1단계: 오류(Error)와 예외(Exception) 이해하기

### 1.1 오류란?

**오류**란 특정한 언어에서 정해진 문법을 따르지 않는 명령이 입력되어 프로그램이 문제를 일으키는 것을 말합니다.

### 1.2 오류의 두 종류

| 종류 | 설명 | 발생 시점 |
|------|------|-----------|
| **구문 오류 (Syntax Error)** | 문법을 지키지 않아 발생하는 오류 (문법 오류, 파싱 오류) | 프로그램 실행 **전** |
| **예외 (Exception)** | 문법은 맞지만 실행 도중 발생하는 오류 | 프로그램 실행 **중** |

### 1.3 구문 오류 예시

```python
# 따옴표를 빠뜨린 경우
print("Hello)   # SyntaxError 발생
```

### 1.4 예외 예시

```python
# 문법은 정상이지만 실행 중 오류
a = 10
b = 0
result = a / b   # ZeroDivisionError 발생
```

### 1.5 자주 발생하는 예외 종류

| 예외 이름 | 발생 상황 |
|-----------|-----------|
| `ZeroDivisionError` | 0으로 나눌 때 |
| `ValueError` | 값의 형식이 잘못된 경우 (예: `int('사백')`) |
| `TypeError` | 자료형이 맞지 않는 연산 (예: `1 + '가'`) |
| `IndexError` | 리스트의 범위를 벗어난 인덱스 사용 |
| `FileNotFoundError` | 파일을 찾을 수 없을 때 |
| `UnicodeDecodeError` | 문자 인코딩을 해석할 수 없을 때 |

### 💡 역추적(Traceback)
파이썬은 예외가 발생하면 오류가 발생한 위치와 종류를 추적해서 알려줍니다. 이 정보를 잘 읽으면 오류 해결에 큰 도움이 됩니다.

## 2단계: `try-except` 기본 문법

### 2.1 기본 구조

```python
try:
    # 예외가 발생할 우려가 있는 코드
    위험한 코드
except:
    # 예외가 발생했을 때 처리할 내용
    예외 처리 코드
```

### 2.2 동작 방식

- 예외가 **발생하지 않으면** → `except` 절을 건너뜀
- 예외가 **발생하면** → `except` 절로 제어 이동

### 2.3 실습 예제

```python
# 기본 try-except 사용
try:
    a, b = input('두 수를 입력하시오: ').split()
    result = int(a) / int(b)
    print(result)
except:
    print('오류가 발생했습니다.')
```

### 2.4 예외 정보 출력하기

`Exception as e` 문법을 사용하면 어떤 예외가 발생했는지 확인할 수 있습니다.

```python
try:
    result = 1 + 1.0 + '문자열'
except Exception as e:
    print('오류 발생:', e)
```

### 💡 핵심 포인트
`try-except`를 사용하면 프로그램이 갑자기 종료되지 않고 사용자에게 대처 방법을 제시할 수 있어 **안정적인 프로그램**을 만들 수 있습니다.

## 3단계: 구체적인 예외 명시하기

### 3.1 왜 구체적인 예외를 명시해야 할까?

예외의 종류가 매우 많기 때문에 어떤 예외인지에 따라 다른 처리가 필요한 경우가 많습니다.

### 3.2 구조

```python
try:
    위험한 코드
except 예외이름1:
    예외1 처리
except 예외이름2:
    예외2 처리
except Exception as e:   # 그 외 모든 예외 처리
    print('알 수 없는 오류:', e)
```

### 3.3 실습 예제

```python
try:
    a = int(input('정수 입력: '))
    b = int(input('정수 입력: '))
    result = a / b
    print(result)
except ZeroDivisionError:
    print('0으로 나눌 수 없습니다.')
except ValueError:
    print('정수가 아닌 값을 입력했습니다.')
except Exception as e:
    print('기타 오류:', e)
```

### 💡 안전한 코딩 팁
구체적인 `except XXX:`와 함께 `except Exception as e:`를 함께 사용하면 더 안전합니다.

## 4단계: `try-except-else-finally` 문

### 4.1 `else` 절

- 예외가 **발생하지 않은 경우**에만 실행
- 반드시 `except` 절 **바로 다음**에 위치해야 함

### 4.2 `finally` 절

- 예외 발생 여부와 **상관없이 항상 실행**
- 파일 닫기, 자원 반환 등에 자주 사용

### 4.3 전체 구조

```python
try:
    # 위험한 코드
except 예외이름:
    # 예외 처리
else:
    # 예외가 발생하지 않을 때만 실행
finally:
    # 항상 실행
```

### 4.4 실습 예제

```python
# try_except_else_test.py
try:
    a, b = input('두 수를 입력하시오: ').split()
    result = int(a) / int(b)
except ZeroDivisionError:
    print('오류 : 0으로 나눔을 시도했습니다.')
except ValueError:
    print('오류 : 입력 값이 정수나 실수가 아닙니다.')
except:
    print('오류 : 10 2와 같이 두 정수를 입력하세요.')
else:
    print('{} / {} = {}'.format(a, b, result))
```

### 4.5 입력별 동작 결과

| 입력 | 동작 |
|------|------|
| `10 2` (정상) | `else` 실행 → `10 / 2 = 5.0` 출력 |
| `10 0` | `ZeroDivisionError` → "0으로 나눔을 시도했습니다." |
| `십 이` (한글) | `ValueError` → "정수나 실수가 아닙니다." |

### 4.6 `finally` 예제

```python
def divide(a, b):
    try:
        result = a / b
        print('결과:', result)
    except ZeroDivisionError:
        print('0으로 나누는 오류 발생')
    finally:
        print('수행 완료')   # 예외 발생 여부와 상관없이 항상 실행

divide(100, 2)   # 결과: 50.0 / 수행 완료
divide(100, 0)   # 0으로 나누는 오류 발생 / 수행 완료
```

## 5단계: `raise` 문으로 예외 발생시키기

### 5.1 `raise` 란?

사용자가 **직접 예외를 발생**시킬 때 사용합니다.

### 5.2 기본 사용법

```python
raise Exception('Exception raised')
```

### 5.3 한글 메시지 사용하기

```python
raise Exception('예외 발생!')
```

### 5.4 실습 예제: 입력값 검증

```python
def get_ans(ans):
    if ans != '예' and ans != '아니오':
        raise ValueError('예/아니오를 입력하세요')
    print('정상적인 입력입니다.')

# 사용
try:
    get_ans('예')        # 정상
    get_ans('예-쓰')      # ValueError 발생
except ValueError as e:
    print('오류:', e)
```

### 💡 활용 시점
- 사용자 입력의 유효성 검사
- 함수의 인자 값이 예상과 다를 때
- 비즈니스 로직 상의 잘못된 상황 알림

### 5.5 내장 예외(Built-in Exception)

`Exception` 클래스는 계층적 구조로 만들어져 있습니다. 새로운 예외를 만들 때는 `Exception`을 **상속받아** 구현합니다.

> 📌 클래스와 상속은 추후 별도 장에서 다룹니다.

## 6단계: 파일 입출력 기초

### 6.1 파일이란?

**파일(file)**: 컴퓨터의 저장 장치 내에 데이터를 저장하기 위해 사용하는 논리적인 단위

- 하드 디스크, 외장 디스크 등에 저장
- 필요할 때 다시 불러서 사용 가능

### 6.2 파이썬에서 파일 사용 절차

```
[1] 파일 열기  →  [2] 파일 사용  →  [3] 파일 닫기
   open()         read/write           close()
```

| 단계 | 설명 |
|------|------|
| **파일 열기** | 저장 장치 내의 위치(경로, path)와 파일 이름을 지정 |
| **파일 사용** | 내용 확인, 새로운 내용 추가, 기존 내용 삭제 등 |
| **파일 닫기** | 사용한 메모리를 시스템에 반환 |

### 6.3 가장 기본적인 파일 쓰기

```python
f = open('hello.txt', 'w')   # 'w' 모드로 파일 열기 (쓰기 전용)
f.write('Hello World!')       # 내용 쓰기
f.close()                     # 파일 닫기
```

| 함수/메소드 | 설명 |
|-------------|------|
| `open()` | 파일을 열고 파일 객체를 반환 |
| `write()` | 파일에 텍스트 쓰기 |
| `close()` | 파일 닫기 (메모리 반환) |

## 7단계: 파일 모드와 읽기/쓰기/추가

### 7.1 `open()` 함수의 인자

```python
open(파일이름, 모드, encoding='인코딩방식')
```

- `파일이름`: 열고자 하는 파일의 이름 또는 경로
- `모드`: 파일을 어떻게 다룰지 지정
- `encoding`: 파일의 인코딩 형식 지정 (예: `'UTF8'`)

> 📌 경로를 지정하지 않으면 디폴트 경로는 **파이썬 스크립트 파일이 있는 곳**입니다.

### 7.2 파일 오픈 모드

| 모드 | 의미 | 설명 |
|------|------|------|
| `'r'` | 읽기 (read) | 기본 모드. 파일이 없으면 오류 발생 |
| `'w'` | 쓰기 (write) | 파일이 없으면 새로 생성. 기존 내용은 **삭제** |
| `'a'` | 추가 (append) | 파일의 끝에 내용 추가. 파일이 없으면 새로 생성 |
| `'x'` | 배타적 생성 | 파일이 있으면 오류 발생 |

### 7.3 텍스트/바이너리 모드

| 모드 | 의미 |
|------|------|
| `'t'` | 텍스트 모드 (기본값) |
| `'b'` | 바이너리(이진) 모드 |

### 7.4 모드 조합 예시

| 모드 | 의미 |
|------|------|
| `'wt'` 또는 `'w'` | 텍스트 쓰기 |
| `'wb'` | 바이너리 쓰기 |
| `'r+'` | 읽기 모드, 쓰기도 가능 |
| `'w+'` | 쓰기 모드, 읽기도 가능 |
| `'a+'` | 추가 모드, 읽기도 가능, 파일이 없으면 생성 |

### 💡 특수 문자
- `\n` : 줄바꿈
- `\'` : 작은 따옴표 출력

### 7.5 버퍼링(Buffering)

- 컴퓨터는 데이터를 **버퍼(buffer, 임시 기억공간)**에 모았다가 한꺼번에 읽거나 씁니다.
- `close()` 함수를 호출하면 버퍼의 내용이 디스크로 보내지고 메모리가 비워집니다.
- 따라서 **파일을 사용한 후에는 반드시 `close()`를 호출**해야 합니다.

### 7.6 파일 읽기 메소드

| 메소드 | 설명 |
|--------|------|
| `read()` | 파일 전체 내용을 하나의 문자열로 반환 |
| `read(n)` | n개의 문자만 읽어서 반환 |
| `readline()` | 한 줄을 읽어서 반환 |
| `readlines()` | 모든 줄을 리스트로 반환 |

### 7.7 파일 읽기 예제

```python
# 전체 읽기
f = open('hello.txt', 'r')
content = f.read()
print(content)
f.close()

# n개 문자 읽기
f = open('hello.txt', 'r')
print(f.read(5))   # 'Hello'만 출력
f.close()

# 한 줄씩 읽기
f = open('foo.txt', 'r')
line1 = f.readline()
line2 = f.readline()
print(line1.rstrip())   # rstrip()으로 끝의 줄바꿈 제거
print(line2.rstrip())
f.close()
```

### 7.8 파일 추가하기 (append 모드)

```python
# 'a+' 모드 사용
f = open('hello.txt', 'a+')
f.write('\n새로운 줄을 추가합니다.')
f.close()
```

| 모드 | 의미 |
|------|------|
| `a` | 추가(append) 모드 |
| `+` | 기존 파일이 없을 경우 새롭게 파일을 생성 |

### 7.9 종합 예제: 정수 5개 저장하고 합/평균 출력

**(1) 파일 쓰기**
```python
# file_write5.py
f = open('data5.txt', 'w')
for i in range(5):
    num = input('정수 입력: ')
    f.write(num + '\n')
f.close()
```

**(2) 파일 읽기 및 합/평균 계산**
```python
# file_read5.py
f = open('data5.txt', 'r')
total = 0
count = 0
for line in f:
    total += int(line)   # 문자열을 정수로 변환
    count += 1
f.close()

print('합:', total)
print('평균:', total / count)
```

> 📌 파일에 저장된 `10`은 문자열 `'10'`이므로 반드시 `int()`로 변환해야 덧셈 연산이 가능합니다.

## 8단계: 파일 입출력과 예외 처리 결합

### 8.1 자주 발생하는 파일 관련 예외

| 예외 | 발생 상황 |
|------|-----------|
| `FileNotFoundError` | 파일을 찾을 수 없을 때 (확장자 빠뜨림 등) |
| `UnicodeDecodeError` | 한글 등 다국어 인코딩 문제 발생 시 |
| `PermissionError` | 파일에 접근할 권한이 없을 때 |

### 8.2 인코딩 문제 해결

한글이 포함된 파일을 읽을 때 `cp949` 코덱만으로는 디코딩할 수 없습니다.
`encoding='UTF8'` 키워드 인자를 지정하여 해결할 수 있습니다.

```python
f = open('한글파일.txt', 'r', encoding='UTF8')
content = f.read()
f.close()
```

### 8.3 파일 이름 오류 처리

```python
import sys

filename = input('파일 이름을 입력하세요: ')

try:
    f = open(filename, 'r', encoding='UTF8')
    for i, line in enumerate(f, 1):
        print('{}: {}'.format(i, line.rstrip()))
    f.close()
except FileNotFoundError as e:
    print('파일을 찾을 수 없습니다:', e)
    sys.exit()
```

### 💡 라인 번호 출력의 활용
라인 번호를 함께 출력하면 개발자가 파일의 어느 줄에서 오류가 발생했는지 쉽게 알 수 있습니다.

### 💬 안전한 코딩의 중요성

> "안전한 코딩은 중요하다! 따라서 예외처리문이 필요하다!!"

파일 입출력은 외부 환경(파일 시스템)에 의존하기 때문에, 항상 예외 처리를 함께 작성해야 안정적인 프로그램을 만들 수 있습니다.

## 9단계: `with` 문으로 안전한 코드 작성

### 9.1 컨텍스트 매니저(Context Manager)란?

**컨텍스트 매니저**: 파일, 네트워크 연결, 데이터베이스 연결과 같이 **리소스를 사용하고 해제**하는 과정을 효율적으로 관리하게 도와주는 객체

- `__enter__()` 메소드: 컨텍스트에 들어갈 때 자동 실행
- `__exit__()` 메소드: 컨텍스트에서 빠져나올 때 자동 실행

### 9.2 `with` 문의 장점

`try-except-finally`를 대신하여 더욱 쉽게 사용할 수 있으며, 파일을 자동으로 닫아주기 때문에 `f.close()`를 명시적으로 호출할 필요가 없습니다.

### 9.3 기본 문법

```python
with open(파일이름, 모드) as 파일객체:
    # 파일 사용 코드
# 블록을 빠져나오면 자동으로 파일이 닫힘
```

### 9.4 비교: 기존 방식 vs `with` 문

**❌ 기존 방식 (close 누락 위험)**
```python
f = open('hello.txt', 'w')
f.write('Hello')
f.close()   # 깜빡 잊으면 메모리 누수!
```

**✅ try-finally 방식 (안전하지만 복잡)**
```python
f = open('hello.txt', 'w')
try:
    f.write('Hello')
finally:
    f.close()
```

**✨ `with` 문 (간결하고 안전)**
```python
with open('hello.txt', 'w') as f:
    f.write('Hello')
# 자동으로 close() 호출
```

### 9.5 `with` 문의 다른 활용 예: 웹페이지 열기

`with` 구문은 파일 외에도 다양한 리소스 관리에 사용됩니다.

```python
from urllib.request import urlopen

with urlopen('https://www.python.org') as response:
    html = response.read()
    print(html[:100])
# 자동으로 인터넷 접속 종료 (close() 호출)
```

> 📌 `with` 문을 사용하지 않으면 파이썬 프로그램이 인터넷 접속을 계속 유지하여 **메모리 낭비**가 발생할 수 있습니다.

# 🔐 보너스 섹션: Secure Coding (안전한 코딩)

## Secure Coding이란?

**Secure Coding(시큐어 코딩)**은 단순히 "동작하는 코드"가 아닌, **악의적인 입력이나 예상치 못한 상황에서도 안전하게 동작하는 코드**를 작성하는 것을 의미합니다.

### 왜 학생 때부터 알아야 할까요?

> 💬 "내 프로그램은 나만 쓰는데 보안이 왜 필요해?"

- 작은 실습 프로그램도 결국 **실무 코드의 기초**가 됩니다.
- 처음부터 좋은 습관을 들이면 나중에 큰 사고를 막을 수 있습니다.
- 예외 처리와 파일 입출력은 **보안 취약점이 가장 자주 발생하는 영역**입니다.

### Secure Coding의 기본 원칙

| 원칙 | 설명 |
|------|------|
| **신뢰하지 말라 (Trust No Input)** | 사용자 입력은 무조건 검증한다 |
| **최소 권한 (Least Privilege)** | 꼭 필요한 만큼만 권한을 부여한다 |
| **방어적 프로그래밍 (Defensive Programming)** | 모든 가능한 오류 상황을 미리 대비한다 |
| **실패를 안전하게 (Fail Safely)** | 오류가 발생해도 시스템 전체가 위험해지지 않도록 한다 |

## 🛡️ 보안 주제 1: 입력값 검증 (Input Validation)

### 문제 상황
사용자가 입력한 값을 **검증 없이** 사용하면, 프로그램이 예상치 못한 동작을 하거나 악용될 수 있습니다.

### ❌ 취약한 코드

```python
# 사용자 입력을 그대로 사용 - 위험!
age = int(input('나이를 입력하세요: '))
print('{}년 후 당신은 {}살입니다.'.format(10, age + 10))
```

**문제점:**
- 사용자가 `-100`을 입력하면? → 비논리적인 결과
- 사용자가 `abc`를 입력하면? → `ValueError`로 프로그램 강제 종료
- 사용자가 매우 큰 수를 입력하면? → 메모리 문제 가능

### ✅ 안전한 코드

```python
def get_valid_age():
    """나이를 안전하게 입력받는 함수"""
    while True:
        try:
            age = int(input('나이를 입력하세요 (0~150): '))
            
            # 1. 범위 검증
            if age < 0 or age > 150:
                raise ValueError('나이는 0~150 사이여야 합니다.')
            
            return age
        except ValueError as e:
            print('오류:', e)
            print('다시 입력해 주세요.\n')

age = get_valid_age()
print('{}년 후 당신은 {}살입니다.'.format(10, age + 10))
```

### 💡 검증 체크리스트

- [ ] **타입 검증**: 입력값이 예상한 자료형인가? (`int`, `str` 등)
- [ ] **범위 검증**: 입력값이 허용 범위 안에 있는가?
- [ ] **길이 검증**: 문자열이 너무 길거나 짧지 않은가?
- [ ] **형식 검증**: 이메일, 전화번호 등의 형식이 맞는가?
- [ ] **허용 목록(Allowlist)**: 미리 정한 값들 중 하나인가?

## 🛡️ 보안 주제 2: 경로 조작 (Path Traversal)

### 문제 상황
사용자가 입력한 **파일 경로를 그대로 사용**하면, `../`와 같은 상위 디렉토리 이동을 통해 시스템의 중요한 파일에 접근할 수 있습니다.

### ❌ 취약한 코드

```python
# 사용자가 파일 이름을 직접 입력
filename = input('읽을 파일: ')   # 사용자 입력: ../../etc/passwd
with open(filename, 'r') as f:
    print(f.read())
```

**공격 시나리오:**
- 사용자가 `../../../Windows/System32/config/SAM` 입력
- 사용자가 `../private/secret.txt` 입력
- → 시스템 파일이나 다른 사용자의 파일 노출 가능

### ✅ 안전한 코드

```python
import os

ALLOWED_DIR = './data'   # 허용된 디렉토리만 접근 가능

def safe_read_file(user_filename):
    """안전하게 파일을 읽는 함수"""
    # 1. 파일명에서 경로 구분자 제거 (디렉토리 이동 차단)
    safe_filename = os.path.basename(user_filename)
    
    # 2. 허용된 디렉토리 내의 파일 경로 생성
    full_path = os.path.join(ALLOWED_DIR, safe_filename)
    
    # 3. 정규화된 절대 경로 확인
    real_path = os.path.realpath(full_path)
    allowed_real_path = os.path.realpath(ALLOWED_DIR)
    
    # 4. 허용 디렉토리를 벗어나는지 검증
    if not real_path.startswith(allowed_real_path):
        raise ValueError('허용되지 않은 경로입니다.')
    
    try:
        with open(real_path, 'r', encoding='UTF8') as f:
            return f.read()
    except FileNotFoundError:
        raise FileNotFoundError('파일을 찾을 수 없습니다.')

# 사용 예
try:
    filename = input('파일 이름: ')
    content = safe_read_file(filename)
    print(content)
except (ValueError, FileNotFoundError) as e:
    print('오류:', e)
```

### 💡 핵심 방어 기법

| 기법 | 설명 |
|------|------|
| `os.path.basename()` | 경로에서 파일명만 추출 (디렉토리 부분 제거) |
| `os.path.realpath()` | 심볼릭 링크와 `..`을 모두 해석한 절대 경로 |
| **허용 디렉토리 검증** | 결과 경로가 허용된 디렉토리 안에 있는지 확인 |
| **확장자 검증** | `.txt`, `.csv` 등 허용된 확장자만 처리 |

## 🛡️ 보안 주제 3: 예외 정보 노출 (Information Disclosure)

### 문제 상황
예외 정보를 그대로 사용자에게 보여주면, **시스템 내부 구조나 민감한 정보가 유출**될 수 있습니다.

### ❌ 취약한 코드

```python
# 예외 메시지를 그대로 사용자에게 노출
try:
    with open('/home/admin/config/db_password.txt', 'r') as f:
        data = f.read()
except Exception as e:
    print('오류:', e)
    # 출력 예: [Errno 2] No such file or directory: '/home/admin/config/db_password.txt'
    # → 시스템 경로 구조와 파일명이 그대로 노출됨!
```

**노출되는 정보:**
- 서버의 디렉토리 구조
- 내부 파일명 (관리자만 알아야 할 정보)
- 데이터베이스 비밀번호 파일의 존재 여부
- 운영체제 종류 (`/`는 Linux, `\`는 Windows)

### ✅ 안전한 코드

```python
import logging

# 1. 로그 설정 (개발자용 상세 로그)
logging.basicConfig(
    filename='app.log',
    level=logging.ERROR,
    format='%(asctime)s - %(levelname)s - %(message)s'
)

def read_config_safely():
    """설정 파일을 안전하게 읽기"""
    try:
        with open('/home/admin/config/db_password.txt', 'r') as f:
            return f.read()
    except FileNotFoundError as e:
        # 개발자에게는 상세 로그
        logging.error('설정 파일 읽기 실패: %s', e)
        # 사용자에게는 일반화된 메시지
        print('오류: 시스템 설정을 불러올 수 없습니다. 관리자에게 문의하세요.')
        return None
    except PermissionError as e:
        logging.error('권한 오류: %s', e)
        print('오류: 시스템 설정을 불러올 수 없습니다. 관리자에게 문의하세요.')
        return None
    except Exception as e:
        logging.error('알 수 없는 오류: %s', e)
        print('오류: 일시적인 문제가 발생했습니다. 잠시 후 다시 시도하세요.')
        return None

config = read_config_safely()
```

| 잘못된 예 | 올바른 예 |
|-----------|-----------|
| `[Errno 2] No such file or directory: '/etc/secret.conf'` | `요청하신 정보를 찾을 수 없습니다.` |
| `MySQL Connection failed: user='admin', password='1234'` | `서비스에 일시적인 문제가 있습니다.` |
| `Traceback... line 42 in /app/payment.py` | `처리 중 오류가 발생했습니다.` |

> 📌 **개발자에게는 자세히, 사용자에게는 간결하게** — 이것이 핵심입니다.

## 🛡️ 보안 주제 4: 리소스 누수 (Resource Leak)

### 문제 상황
파일이나 네트워크 연결을 **사용 후 닫지 않으면**, 시스템 자원이 계속 소모되어 결국 프로그램이 멈출 수 있습니다.

### ❌ 취약한 코드 (1): close() 누락

```python
# 파일을 닫지 않음 - 리소스 누수!
def read_files(filenames):
    contents = []
    for name in filenames:
        f = open(name, 'r')
        contents.append(f.read())
        # f.close()를 깜빡 잊음!
    return contents
```

**문제점:**
- 파일 핸들이 계속 쌓임
- OS의 최대 파일 핸들 수 초과 시 프로그램 다운
- 다른 프로그램이 같은 파일에 접근 불가

### ❌ 취약한 코드 (2): 예외 시 close() 누락

```python
def process_file(filename):
    f = open(filename, 'r')
    data = int(f.read())   # ValueError 발생 가능!
    # 예외 발생 시 아래 close()는 실행되지 않음
    f.close()
    return data
```

### ✅ 안전한 코드 (1): `with` 문 사용

```python
def read_files(filenames):
    contents = []
    for name in filenames:
        with open(name, 'r', encoding='UTF8') as f:
            contents.append(f.read())
        # 자동으로 close() 호출됨 (예외 발생 시에도!)
    return contents
```

### ✅ 안전한 코드 (2): 여러 리소스 동시 관리

```python
# 두 파일을 동시에 다룰 때
with open('input.txt', 'r', encoding='UTF8') as fin, \
     open('output.txt', 'w', encoding='UTF8') as fout:
    for line in fin:
        fout.write(line.upper())
# 두 파일 모두 자동으로 닫힘
```

### 💡 리소스가 자동 관리되는 객체들

`with` 문으로 안전하게 관리할 수 있는 리소스:

- 📁 파일 (`open()`)
- 🌐 네트워크 연결 (`urlopen()`, `socket`)
- 🗄️ 데이터베이스 연결 (`sqlite3.connect()`)
- 🔒 잠금/뮤텍스 (`threading.Lock()`)

> ✨ **핵심 규칙**: 리소스를 사용할 때는 항상 `with` 문을 우선 고려하세요!

## 🛡️ 보안 주제 5: 파일 권한과 인코딩 안전성

### 문제 상황 1: 잘못된 인코딩 처리

### ❌ 취약한 코드

```python
# 인코딩을 명시하지 않음
with open('user_data.txt', 'r') as f:
    data = f.read()
    # Windows에서는 cp949, Linux/Mac에서는 UTF-8로 해석됨
    # → OS마다 다른 결과! 한글 깨짐 가능
```

**문제점:**
- 환경에 따라 동작이 다름 (이식성 문제)
- 한글이 포함된 파일에서 `UnicodeDecodeError` 발생
- 외부에서 받은 파일을 처리할 때 예측 불가

### ✅ 안전한 코드

```python
def read_text_safely(filename):
    """다양한 인코딩을 안전하게 처리"""
    encodings = ['UTF-8', 'cp949', 'euc-kr']
    
    for enc in encodings:
        try:
            with open(filename, 'r', encoding=enc) as f:
                return f.read(), enc
        except UnicodeDecodeError:
            continue   # 다음 인코딩 시도
        except FileNotFoundError:
            raise   # 파일 없음은 즉시 알림
    
    raise ValueError('지원되지 않는 인코딩입니다.')

# 사용
try:
    content, encoding_used = read_text_safely('data.txt')
    print(f'[{encoding_used}로 해석됨]')
    print(content)
except (FileNotFoundError, ValueError) as e:
    print('오류:', e)
```

```python
import os
import stat

def save_sensitive_data(filename, data):
    """민감한 데이터를 안전하게 저장"""
    # 1. 파일 생성 (UTF-8 명시)
    with open(filename, 'w', encoding='UTF-8') as f:
        f.write(data)
    
    # 2. 파일 권한 제한 (Unix/Linux/Mac)
    # 0o600 = 소유자만 읽기/쓰기 가능
    if os.name != 'nt':   # Windows가 아닌 경우
        os.chmod(filename, stat.S_IRUSR | stat.S_IWUSR)
    
    print(f'{filename}이(가) 안전하게 저장되었습니다.')

# 사용 (실제 비밀번호는 평문이 아닌 해시로 저장해야 함!)
save_sensitive_data('config.txt', '중요한 설정 데이터')
```
